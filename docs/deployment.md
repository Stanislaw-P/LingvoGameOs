# Docker: сборка и офлайн-доставка

## Полный релиз

На машине сборки нужны Docker/Compose, Python 3.11+ и Git-checkout со всеми
сабмодулями. Установи в рабочем `.env` уникальный `IMAGE_TAG` релиза, например
`2026-10-25-1`, затем выполни:

```powershell
.\stack.ps1 server export .\artifacts\offline\2026-10-25-1
```

Или Linux:

```bash
bash ./stack.sh server export ./artifacts/offline/2026-10-25-1
```

Экспорт собирает final-образы из текущих исходников и добавляет PostgreSQL. Все слои помещаются в `images.tar.gz`. Большой
архив здесь нормален: сервер ничего не догружает. Общие слои Docker сохраняются
один раз. `release.json`/`IMAGES` фиксируют image ID и платформу, `SHA256SUMS`
позволяет проверить перенос. Это пакет приложения, **не резервная копия БД**.

В пакете отсутствуют исходники, `.git`, NuGet/pip-кэш и рабочие секреты. В
экспортированном Compose нет `build` и стоит `pull_policy: never`. `IMAGE_TAG`
в серверном `.env` не переименовывает образы готового релиза: имена уже закреплены.

На сервере с заранее установленными Docker Engine и Compose:

```bash
cp .env.server.example .env
# Заполнить адрес сайта, учётные данные БД, пароли seed-аккаунтов и секреты.
bash ./stack.sh server up
```

Скрипт при необходимости сам проверяет пакет и загружает точные образы.
Для явного предварительного импорта: `bash ./stack.sh server load`.
Исходники и Git на сервере не нужны. `server build` предназначен для машины
сборки; `server up` не выполняет сборку или pull. Скрипты PowerShell имеют тот
же интерфейс. Для другой архитектуры используй
`python deploy/bundle.py --platform linux/arm64 --output <каталог>`.

## Файлы и внешние сервисы

`FILE_STORAGE=local` направляет новые загрузки в `/uploads/` и постоянный
volume `portal-uploads`. Встроенные картинки/скрипты остаются в Web-образе.
Смена режима хранения не скачивает старое содержимое S3: его надо отдельно
перенести вместе с корректными путями в БД. PostgreSQL и игровые volumes также
переносятся отдельной резервной копией, если нужны существующие данные.

Bootstrap, Bootstrap Icons, Font Awesome, Tailwind browser и игровые шрифты
доступны локально под `/vendor/`. Их версии/лицензии лежат рядом с файлами,
обновление на машине с Интернетом: `python deploy/vendor_assets.py`. Для работы
игр браузеру не нужен внешний CDN.

`OFFLINE_MODE=true` выключает Метрику. VK-вход, отправка почты, внешние аватары,
видеоролики и S3 остаются внешними интеграциями и без сети недоступны; обычная
игра гостем и вход по локальному аккаунту работают без них. Для закрытого
сервера не заполняй необязательные OAuth/S3-параметры. Не путай отсутствие
Интернета с Docker `internal`-сетью: на некоторых установках она блокирует и
доступ к опубликованным портам сайта.
